# v0.3.0

[English](v0.3.0.md) | 简体中文

apix v0.3.0 按统一口径报告上游返回的 Token 用量，并大幅提升 SSE 分帧及合成 Responses 流的性能。所有 API 变更均为新增，转换输出不变，仍要求 Go **1.26.10+**。

## 兼容性

- **仅新增 API：**没有删除或修改任何导出标识符。新增的类型和字段见下文；不使用它们的代码行为与之前一致。
- **转换输出不变：**48 份转换快照逐字节一致。Responses 流优化后，每个输出事件与 v0.2.0 逐字节相同。
- **Chat Completions 流用量需显式开启：**`openai.ChatCompletionsOptions{StreamUsage: true}` 为流式请求添加 `stream_options.include_usage`。开启后，原生 Chat Completions 客户端即使未请求，也会收到最后的用量块（`choices` 为空）。默认关闭。
- **网关流响应体现在由互斥锁保护**，确保无论流正常结束、失败还是被关闭，用量回调都只执行一次。回调在锁外调用，可以使用响应体。

## 变更

- **Token 用量：**Exchange 实现可选接口 `apix.UsageReporter`。`Usage()` 返回 `apix.Usage`，普通响应和 SSE 流都直接从上游字节读取。`InputTokens` 包含缓存读写，`OutputTokens` 包含推理，`TotalTokens` 为上游总数或两者之和，`Raw` 保留上游原始用量对象。流会合并多个事件中的用量，例如 Messages 的 `message_start` 与 `message_delta`。覆盖 Chat Completions、Responses、Messages、GenerateContent、Interactions、OpenAI Images 及 Gemini 图像模型；Imagen 不报告用量。
- **网关用量：**`gateway.Config.OnUsage` 在 `Do` 返回普通响应时，以及流结束、失败或被关闭时（携带截至当时的计数）各接收一次已提交尝试的用量。`Handler` 同样适用。`Response.Usage()` 返回相同的值。
- **SSE 分帧：**`sse.Framer.Next` 从上次停止处继续查找行尾，不再重新扫描整个缓冲区，因此跨多个块传输的长行可在线性时间内分帧。3 MiB 的行按 16 KiB 分块时，耗时从 74.7 ms 降至 4.4 ms；原生图像流受益最大。
- **Responses 流：**Chat Completions 流转换为 Responses 时，不再为缺失字段逐个增量构造解码错误，改用按键序声明的结构体而非排序 map 编码增量，并省去二次校验和重新分帧。`BenchmarkStreamChatToResponses`：1.32 → 0.75 ms/op，14327 → 4238 allocs/op。
- **低开销用量跟踪：**跟踪器自行切分 SSE 行并复用缓冲区，只解码包含 `"usage` 的帧。开启跟踪后，同协议 Messages 流的耗时与 v0.2.0 相差约 15% 以内；得益于分帧修复，图像流比之前快约 10 倍。
- **验证工具：**新增 fuzz 目标，在任意分块方式下将 SSE 分帧器与旧实现、用量跟踪器与完整分帧加解码、各流快路径与被替换代码分别比对。全部通过 `make fuzz` 运行。

## 升级

```sh
go get github.com/dillonzq/apix@v0.3.0
```

无需迁移。如需记录用量，可将 Exchange 断言为 `apix.UsageReporter`，或设置 `gateway.Config.OnUsage`；对流式 Chat Completions 上游，还需设置 `openai.ChatCompletionsOptions{StreamUsage: true}`。详见 [Token 用量](../../README.zh-CN.md#token-用量)。
