# v0.2.0

[English](v0.2.0.md) | 简体中文

apix v0.2.0 优化请求检查、JSON 字段编辑、内联媒体 Base64 处理及 Responses 流处理。公开 Go API 和支持的协议转换方向不变，仍要求 Go **1.26.10+**。

## 兼容性

- **一个外部依赖：**生产与测试代码现在依赖 `github.com/MoeForge/moego v0.1.0-alpha.1`，其自身仅依赖标准库。`base64` 包用于媒体校验和编码，`ojson` 用于保序 JSON 读取与编辑。依赖检查仍拒绝其他所有外部模块。
- **JSON 字节输出变化：**修改后的请求和部分 SSE 载荷现在保留未涉及字段的成员顺序、空白和数值写法，不再对整个对象重新编码并排序键。新增成员追加到末尾。JSON 语义保持一致，但按精确字节比较的调用方需要审阅测试样本。按项目 1.0 之前的版本约定，此线协议输出变化以次版本发布。
- 快路径拒绝歧义键、非对象父节点及无效 JSON，由调用方回退到既有 `encoding/json` 路径。回退仍可能重新编码并排序，因此成员顺序并非无条件保证。
- moego 默认分配器使用 `//go:linkname runtime.mallocgc`。可通过 `-tags moego_zeroalloc` 或 `-tags purego` 构建以使用普通分配。详见[设计规则](../../CONTRIBUTING.md#design-rules)。

## 变更

- **请求编辑：**原生模型改写、推理覆盖与被取代控制的移除、Responses 工具规范化及原生图像模型/流标记改写，在适用时使用 `internal/jsonedit`。这些快路径保留无关字段的字节。
- **路由检查：**LLM 共享路由字段及特征扫描使用 ojson；请求转换仅需要路由值与协议校验时跳过特征扫描。受保护的读取和回退路径保持重复键及字符串解码与 `encoding/json` 兼容。
- **媒体：**内联 LLM 媒体和图像载荷的 Base64 校验及编码使用 moego；文本文档转换在需要时仍解码并校验 UTF-8。
- **流：**合成 Responses 序号及原生函数调用事件的工具身份恢复，在可行时仅编辑相关字段。未修改的原生帧及原生序号保持不变。
- **SSE 分帧修复：**修改后的多行 JSON 在包装到 `data:` 字段前先压紧，防止内部换行截断事件载荷。
- **验证工具：**新增请求、检查、流和媒体基准测试，以及 JSON 编辑和差分 fuzz 测试，覆盖优化路径、歧义键、精确数值与标准库行为一致性。

## 升级

```sh
go get github.com/dillonzq/apix@v0.2.0
```

无需迁移公开 API。请更新依赖白名单及按精确 JSON 字节断言的测试样本。快路径与回退细节见[架构说明](../architecture.zh-CN.md#json-读取与编辑)。
