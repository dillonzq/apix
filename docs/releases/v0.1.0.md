# v0.1.0

apix 的首个版本提供通用 API 转换与路由接口，内置五种 LLM 协议。要求 Go **1.26.10+**，生产与测试代码仅依赖标准库。

## 新增能力

- **通用核心**：根包 `apix` 定义 `Kind`、`Protocol`、`Payload`、`ProtocolSpec`、`Codec`、`Exchange` 和显式的 `Registry`，不与具体协议绑定。图像生成、语音等新的接口类型都通过同一套接口接入，见[扩展指南](../extending.zh-CN.md)。公开函数返回 `error`，其值为 `*apix.Error`，用 `apix.AsError` 读取。
- **按供应商组织的协议包**：协议 ID 带命名空间。
  - `protocol/openai`：`openai.chat-completions`、`openai.responses`；
  - `protocol/anthropic`：`anthropic.messages`；
  - `protocol/gemini`：`gemini.generate-content`、`gemini.interactions`（仅原生）。
- **路由**：`route.Router` 的排序规则如下：
  - 同协议端点优先，可以零转换透传；
  - 没有可用的同协议端点时，降级到同类接口中可转换的协议；
  - 同一层内按优先级和权重排序；
  - 默认的 `Breaker` 跳过持续失败的端点，暂停结束后每次只放行一个试探请求，并遵循上游的 `Retry-After`；
  - 引用上游状态的请求优先发往持有该状态的端点，延续上游上下文的请求只走同协议；
  - 支持模型别名与通配，端点集合可以原子热更新，端点选项在配置阶段校验。

  详见[路由](../routing.zh-CN.md)。
- **网关**：可选的 `gateway` 包负责 HTTP 执行、鉴权注入和流式代理，并提供 `http.Handler`：
  - 提交点之前，可重试的失败会自动切换到下一个候选；`CommitTimeout` 限制到达提交点的时间；
  - 提交点之后不再重试；
  - 返回的错误使用客户端协议的格式，并转告上游的 `Retry-After`；
  - `ForwardHeaders` 选择透传的上游响应头，`ReasoningSuffix` 支持 `model(high)` 后缀。

## LLM 转换

- Chat Completions、Responses、Messages 与 GenerateContent 之间共十二个方向的直接转换，覆盖请求、普通响应和流式响应；`Exchange` 保存工具身份与转换诊断。`Output` 选项允许响应使用独立于请求的协议；网关通过 `gateway.Request.Output` 指定。
- `LossPolicy` 控制请求转换中的信息丢失，`Diagnostics()` 返回诊断。
- `ExchangeOptions.Reasoning` 为任意上游覆盖推理控制，按上游自身的推理选项渲染。
- `openai.ResponsesOptions` 配置原生 Responses 工具规范化，`anthropic.MessagesOptions` 配置无签名 thinking 回传与 thinking 模式，`gemini.GenerateContentOptions` 配置 Gemini 推理模式与签名要求。
- `reasoning` 提供推理档位和模型名称后缀处理，`sse.Decoder` 提供独立的 SSE 解码能力。
- 上游 Responses 流未提供响应 ID 时，跨协议转换使用 `apix` 作为默认 ID。

## 验证

48 份转换快照覆盖请求、响应与流式输出；一致性测试逐字节比较各 Exchange 组合与 LLM 引擎的结果。网关测试覆盖故障切换、提交点与超时、熔断、亲和性、配置热更新及鉴权；竞态测试检查并发使用，模糊测试检查流式分块与终止状态。
