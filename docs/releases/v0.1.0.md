# v0.1.0

apix 的首个版本提供通用 API 转换与路由接口，内置三种 LLM 协议。要求 Go **1.26.7+**，生产与测试代码仅依赖标准库。

## 新增能力

- **通用核心**：根包 `apix` 定义 `Kind`、`Protocol`、`Payload`、`ProtocolSpec`、`Codec`、`Exchange` 和显式的 `Registry`，不与具体协议绑定。图像生成、语音等新的接口类型都通过同一套接口接入，见[扩展指南](../extending.zh-CN.md)。
- **按供应商组织的协议包**：`protocol/openai` 提供 `openai.chat-completions` 和 `openai.responses`，`protocol/anthropic` 提供 `anthropic.messages`。协议 ID 带命名空间。
- **路由**：`route.Router` 的排序规则如下：
  - 同协议端点优先，可以零转换透传；
  - 没有可用的同协议端点时，降级到同类接口中可转换的协议；
  - 同一层内按优先级和权重排序；
  - 默认的 `Breaker` 会跳过持续失败的端点；
  - 支持模型别名与通配，端点集合可以原子热更新。

  详见[路由](../routing.zh-CN.md)。
- **网关**：可选的 `gateway` 包负责 HTTP 执行、鉴权注入和流式代理，并提供 `http.Handler`：
  - 提交点之前，可重试的失败会自动切换到下一个候选；
  - 提交点之后不再重试；
  - 返回的错误使用客户端协议的格式。

## LLM 转换

- `Exchange` 支持请求、普通响应和流式响应转换，并保存工具身份与转换诊断。`Output` 选项允许响应使用独立于请求的协议；网关通过 `gateway.Request.Output` 指定。
- `LossPolicy` 控制请求转换中的信息丢失，`Diagnostics()` 返回诊断。
- `openai.ResponsesOptions` 配置原生 Responses 工具规范化，`anthropic.MessagesOptions` 配置无签名 thinking 回传。
- `reasoning` 提供推理档位和模型名称后缀处理，`sse.Decoder` 提供独立的 SSE 解码能力。
- 上游 Responses 流未提供响应 ID 时，跨协议转换使用 `apix` 作为默认 ID。

## 验证

27 份转换快照覆盖请求、响应与流式输出；一致性测试逐字节比较各 Exchange 组合与 LLM 引擎的结果。网关测试覆盖故障切换、提交点、配置热更新及鉴权；竞态测试检查并发使用。
