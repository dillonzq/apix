# v0.1.0

English | [简体中文](v0.1.0.zh-CN.md)

The first apix release provides a protocol-neutral API conversion and routing interface, with five built-in LLM protocols and four image generation and editing protocols. It requires Go **1.26.10+**, and production and test code depend on the standard library only.

## Highlights

- **Protocol-neutral core**: the root package `apix` defines `Kind`, `Protocol`, `Payload`, `ProtocolSpec`, `Codec`, `Exchange`, and an explicit `Registry`, tied to no particular protocol. The image Kind is built on these interfaces, and speech and other kinds plug in the same way; see [adding protocols and kinds](../extending.md). Public functions return `error`; values are `*apix.Error`, read with `apix.AsError`.
- **Protocol packages by vendor**, with namespaced protocol IDs:
  - `protocol/openai`: `openai.chat-completions`, `openai.responses`, and the image protocols `openai.images.generations` and `openai.images.edits`;
  - `protocol/anthropic`: `anthropic.messages`;
  - `protocol/gemini`: `gemini.generate-content`, `gemini.interactions` (native only), and the image protocols `gemini.generate-content.image` and `gemini.imagen`.
- **Routing**: `route.Router` orders candidates as follows:
  - same-protocol endpoints come first and pass through without conversion;
  - when none is available, it falls back to convertible protocols of the same Kind;
  - within a tier, endpoints are ordered by priority and weight;
  - the default `Breaker` skips endpoints that keep failing, admits one trial request after the cooldown, and honors upstream `Retry-After`;
  - requests that reference upstream state go first to the endpoint holding it, and requests that continue upstream context stay on the same protocol;
  - model aliases and wildcards are supported, the endpoint set can be swapped atomically at runtime, and endpoint options are validated when configured.

  See [routing](../routing.md).
- **Gateway**: the optional `gateway` package performs HTTP execution, credential injection, and stream proxying, and provides an `http.Handler`:
  - before the commit point, retryable failures fail over to the next candidate; `CommitTimeout` bounds the time to reach it;
  - after the commit point, nothing is retried;
  - errors are returned in the client protocol's format and pass on the upstream `Retry-After`;
  - `ForwardHeaders` selects upstream response headers to forward, and `ReasoningSuffix` enables `model(high)` suffixes.

## LLM conversion

- Direct conversion in all twelve directions among Chat Completions, Responses, Messages, and GenerateContent, covering requests, responses, and streams; an `Exchange` keeps tool identities and conversion diagnostics. The `Output` option lets the response use a protocol other than the request's; the gateway sets it through `gateway.Request.Output`.
- `LossPolicy` governs information loss in request conversion, and `Diagnostics()` reports it.
- `ExchangeOptions.Reasoning` overrides reasoning controls for any upstream, rendered in that upstream's own reasoning options.
- `openai.ResponsesOptions` configures native Responses tool normalization, `anthropic.MessagesOptions` configures unsigned thinking replay and the thinking mode, and `gemini.GenerateContentOptions` configures the Gemini reasoning mode and signature requirements.
- `reasoning` provides reasoning levels and model-name suffix handling, and `sse.Decoder` decodes SSE on its own.
- When an upstream Responses stream carries no response ID, cross-protocol conversion uses `apix` as the default ID.

## Image conversion

- Direct conversion among OpenAI Images (generations and edits), GenerateContent sent to image models (such as `gemini-2.5-flash-image`), and Imagen: generations ↔ GenerateContentImage / Imagen, edits ↔ GenerateContentImage, and Imagen ↔ GenerateContentImage. Image requests route only to image endpoints.
- Requests map prompts, inline input images (multipart or JSON edits), counts, sizes and aspect ratios, and output formats; fields that cannot be represented are reported as diagnostics and checked against `LossPolicy`. Input that would need I/O (OpenAI file IDs, remote URLs, `fileData`) is not converted, and affinity keys send it to native endpoints first.
- Responses map images, candidates, and usage. A response without images is an error: safety and policy stops are not retryable, and other stops fail over to another upstream.
- Native streams pass through validated; a cross-protocol streaming request calls the upstream without streaming and returns the client protocol's complete event stream.
- `gemini.GenerateContentImageOptions` sets `responseModalities` on converted and native requests. See [image protocol conversion](../protocols/image.md).

## Verification

48 conversion snapshots cover requests, responses, and streams, and parity tests compare every Exchange combination with the LLM engine byte for byte. Gateway tests cover failover, the commit point and timeout, the breaker, affinity, runtime reconfiguration, and authentication. Race tests check concurrent use, and fuzz tests check stream chunking and terminal states as well as image request, response, and stream conversion.
