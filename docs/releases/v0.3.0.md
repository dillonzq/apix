# v0.3.0

English | [简体中文](v0.3.0.zh-CN.md)

apix v0.3.0 reports the token usage that upstreams return, in one accounting for every protocol, and makes SSE framing and synthesized Responses streams substantially faster. All API changes are additive, conversion output is unchanged, and Go **1.26.10+** is still required.

## Compatibility

- **Additive API only:** no exported identifier was removed or changed. The new types and fields are listed below; code that ignores them behaves as before.
- **Conversion output is unchanged:** the 48 conversion snapshots are byte-identical. The Responses stream optimizations keep every emitted event byte-for-byte equal to v0.2.0.
- **Chat Completions stream usage is opt-in:** `openai.ChatCompletionsOptions{StreamUsage: true}` adds `stream_options.include_usage` to streamed requests. When it is set, native Chat Completions clients also receive the final usage chunk (empty `choices`), even if they did not ask for it. It is off by default.
- **Gateway stream bodies are now guarded by a mutex** so the usage callback can run exactly once whether a stream ends, fails, or is closed. The callback is invoked outside the lock and may use the body.

## Changes

- **Token usage:** exchanges implement the optional `apix.UsageReporter`. `Usage()` returns `apix.Usage`, read from the upstream bytes of ordinary responses and SSE streams alike. `InputTokens` includes cache reads and writes, `OutputTokens` includes reasoning, `TotalTokens` is the upstream total or the sum, and `Raw` keeps the upstream usage object. Streams merge usage across events, such as Messages `message_start` and `message_delta`. Chat Completions, Responses, Messages, GenerateContent, Interactions, OpenAI Images, and Gemini image models are covered; Imagen reports no usage.
- **Gateway usage:** `gateway.Config.OnUsage` receives the committed attempt's usage when `Do` returns an ordinary response, and once a stream ends, fails, or is closed (with the counts seen so far). It also works with `Handler`. `Response.Usage()` returns the same value.
- **SSE framing:** `sse.Framer.Next` resumes its line-end search where the previous call stopped instead of rescanning the buffer, so a long line delivered across many chunks frames in linear time. A 3 MiB line in 16 KiB chunks went from 74.7 to 4.4 ms; native image streams benefit most.
- **Responses streams:** converting Chat Completions streams to Responses skips per-delta decode errors for absent fields, encodes deltas from ordered structs instead of sorted maps, and avoids a second validation and re-framing pass. `BenchmarkStreamChatToResponses`: 1.32 → 0.75 ms/op, 14327 → 4238 allocs/op.
- **Low-overhead usage tracking:** the tracker splits SSE lines itself, reuses its buffers, and decodes only frames containing `"usage`. With tracking enabled, same-protocol Messages streams stay within about 15% of v0.2.0, and image streams are about 10× faster than before thanks to the framer fix.
- **Validation tools:** new fuzz targets check the SSE framer against its previous implementation, the usage tracker against full framing and decoding under every chunk split, and each stream shortcut against the code it replaces. All run with `make fuzz`.

## Upgrade

```sh
go get github.com/dillonzq/apix@v0.3.0
```

No migration is needed. To record usage, type-assert an exchange to `apix.UsageReporter` or set `gateway.Config.OnUsage`; for Chat Completions upstreams that stream, also set `openai.ChatCompletionsOptions{StreamUsage: true}`. See [token usage](../../README.md#token-usage).
